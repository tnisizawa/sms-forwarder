# SMS転送の運用仕様

スプレッドシートの「SMS転送」メニューの動作と、ログ保持・再送・復旧の決めごとをまとめます。シートの列や設定値は [SHEETS_SPEC.md](SHEETS_SPEC.md) を参照してください。

## SMS転送メニュー

スプレッドシートを開くと「SMS転送」メニューに次の3項目が表示されます。表示だけでは初期化・送信しません。操作時は Gmail と現在のシートの権限に加え、ダイアログ用の script.container.ui の承認が必要です。

- 初期設定: settings・log・filter を補完します。GAS エディタの setup も同じ処理です。既存値・ルール・ログを削除せず、2回目以降も値を保持します。ヘッダー不一致では自動修復せず停止します。
- スマホの設定手順をメールで送る: ウェブアプリをデプロイし、公開画面に表示された URL（/exec で終わる）を settings の「ウェブアプリURL」へ貼り付けてから実行すると、自分宛へ手順メールを送ります。転送先アドレスを別に設定していても手順メールは自分宛です。URL は形式だけを確認し、公開状態・到達可能性・スクリプトとの対応は保証しません（正しい公開 URL の貼り付けは利用者の責任）。未入力や不正形式では送らず、貼り付けを案内します。
- テスト送信: 現在の filter で判定したテスト SMS を、現在の転送先へ送ります。不通過ではメールを送らず、その旨を表示します。結果は log へ記録し、通常の保持上限を適用します。

合言葉を再生成する場合は settings の値を明示的に消し、初期設定を実行します。その後は端末側の合言葉も更新し、新しい手順メールを使って再設定してください。ログや他の設定は保持します。

## ログ保持の決めごと

- `log` は長期保管庫ではなく、転送結果を切り分けるための直近の履歴です。
- 設定した保持上限を超えた古いデータ行は自動削除します。ヘッダー行は保持件数に含めず、削除しません。
- 通常のローテーションでは、削除のたびにバックアップを作りません。この点だけ「破壊的操作の前に毎回バックアップする」ルールの例外とします。
- 保持上限を小さくすると、次のログ記録時に既存の古い行も削除対象になります。必要な履歴は設定変更前に別途保存してください。
- この例外は `log` の保持上限による削除に限ります。`settings`、`filter`、メールや、ログの別用途の上書き・削除には適用しません。

保持件数は `settings` の「ログの保持行数」で変更します。既定はデータ1,000行。空欄、不正値、0以下、小数は既定へ戻ります。

## 再送と失敗の切り分け

同じ端末・SIM・送信元・本文・受信時刻の再送は、送信済みの短期キャッシュが残っている場合に抑止します。保持期間の指定は10分ですが、サービスの都合で早期に消えることがあり、恒久的な二重送信防止は保証しません。受信時刻がない旧端末では、同じ内容の別のSMSを短期間に受けると重複扱いになる場合があります。

重複の応答は正常終了で、`mailed=false`、理由は `duplicate` です。認証されていない要求は既定で `log` に記録しません。切り分け用の「未認証も記録する」を有効にしても、SMS本文や電話番号、合言葉は残しません。

同時着信はスクリプト内のロック取得を最大30秒待って直列化します。待機上限に達した要求は、メールもログも更新しません。GAS実行履歴を確認し、失敗した要求は端末の送信履歴から手動再送してください。HTTP成功の応答に失敗JSONが含まれていても、SmsForwarderが自動再送するとは限りません。

メール送信後のラベル、キャッシュ記録、ログ記録の失敗は警告として扱い、送信済みの結果を失敗へ戻しません。警告はGASの実行履歴を確認してください。キャッシュ記録失敗後の再送や、Gmailの通信障害で送信成否が不明になった場合、実行の強制終了では二重送信を防げないことがあります。

## 復旧時の注意

コードを旧バージョンへ戻しても、削除したログは戻りません。ローテーションで削除された行は、別途保存していなければ復旧できません。

復旧は受信処理を止めてから、現在のログを退避し、バックアップのヘッダーと値を元の `log` へ戻して読み直します。受信停止・再開は、利用者の確認を得て行います。
